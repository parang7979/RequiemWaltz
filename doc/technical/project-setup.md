# 프로젝트 설정과 실행

## 제작 가능성

이 구성으로 제작할 수 있다. 석교 시험 장면에서 GDScript 물리 이동, 도트 배율, 패럴랙스, 방향별 노멀·발광, 접지 이펙트와 음원을 한 화면에 연결했다. 지금 남은 가장 큰 제작 변수는 무기 수와 동작 수다. 한 자루를 추가하면 지상·공중 동작, 다른 무기에서 넘어오는 자세, 명중·헛침 타이밍과 적 반응을 함께 검토해야 한다.

첫 전투실에서는 무기 두 자루와 소형 적 하나로 그 비용을 측정한다. 환경 디테일은 같은 방에서 가장 밝은 공격을 쓴 순간까지 확인한다. 물 반사가 적의 팔을 묻거나 나뭇가지가 착지점을 가리면 해당 레이어의 밝기·속도·위치를 조정한다. 대화 원화는 석교와 다른 해상도·조명 요구가 있어, 별도 대화 장면에서 한 얼굴의 품질을 확인한 뒤 수량을 정한다.

## 실행 환경

엔진 표준판에서 확인한 버전은 `4.7.2.stable.official.ed1daf0bf`다. 게임 로직은 GDScript이며, 배포한 게임은 렌더된 PNG와 음원을 직접 사용한다. 아래 명령은 저장소 루트에서 실행한다.

```powershell
$godotDir = 'C:\Godot_v4.7.2-stable_win64.exe'
& "$godotDir\Godot_v4.7.2-stable_win64.exe" --editor --path .
```

F5로 기본 장면 [석교](../../scenes/rooms/causeway.tscn)를 연다. 왼쪽에서는 달빛, 오른쪽에서는 창문 쪽의 따뜻한 빛이 검과 옷의 노멀맵에 반응한다. 발 피벗을 석교 충돌면에 맞췄고, 이동 방향에 따라 왼손·오른손과 광원 방향이 보존된 측면 이미지를 선택한다. 현재 움직임에는 양방향 정지 포즈를 사용한다. 달리기와 공중 공격 클립은 첫 전투실의 작업이다.

## 화면과 입력

| 설정 | 기준 |
| --- | --- |
| 논리 해상도 | 640×360. 기본 창은 1280×720. 16:9 화면 비율 유지, 정수 배율, `viewport` 스트레치 |
| 픽셀과 카메라 | 최근접 필터와 2D 변환 픽셀 스냅. 물리 위치는 소수 정밀도를 유지한다. 카메라 이동 범위는 방의 경계로 정한다. |
| 렌더링 | GL Compatibility. 원경은 구워진 색으로 두고, 캐릭터·석교의 노멀은 국소 광원 두 개에 반응한다. 브로치는 가산 발광 레이어를 사용한다. |
| 시간 | 물리 60틱/초. 추후 공격 활성 구간, 입력 예약, 교체 취소 구간을 물리 시간으로 판정한다. |
| 현재 입력 | A/D, ←/→, 패드 십자키·왼쪽 스틱으로 이동. Space 또는 패드 아래쪽 버튼으로 점프. 짧게 눌러 낮게 뛸 수 있다. F11로 전체 화면 전환. |
| 다음 단계용 InputMap | 약공격 J/패드 왼쪽, 강공격 K/위쪽, 회피 Shift/오른쪽, 교체 Q/오른쪽 숄더, 상호작용 E/왼쪽 숄더, 지도 M/뷰 버튼, 스킬 I. 실제 동작은 각 시스템 구현 시 연결한다. |

정수 배율에서 남는 공간은 레터박스로 처리한다. 전투 에셋과 메뉴를 만들 때 1배율과 2배율을 함께 확인한다. 한글 대사와 작은 수치는 실제 표시 크기에서 읽어 보고, 필요하면 대화·메뉴에 고해상도 UI 뷰포트를 따로 검토한다. [Godot 다중 해상도](https://docs.godotengine.org/en/4.7/tutorials/rendering/multiple_resolutions.html) · [Godot 2D 조명](https://docs.godotengine.org/en/4.7/tutorials/2d/2d_lights_and_shadows.html)

## 게임 로직과 자산 경계

- `scenes/actors/`에서 이동·점프·접지를 처리한다. `CharacterBody2D`가 공중에서 바닥으로 돌아올 때 한 번 발 위치를 알린다. 방은 그 위치에서 먼지와 소리를 재생한다.
- 충돌 레이어는 1 지형, 2 플레이어, 3 적, 4 플레이어 타격, 5 적 타격, 6 상호작용으로 이름을 정했다. 첫 전투실에서는 이동 충돌과 공격·피격 판정을 나누고, 공격 한 번이 같은 대상에 몇 번 맞을 수 있는지 동작별로 정한다.
- 오디오 버스는 Master 아래 SFX, Ambience, Music, UI다. 착지음은 SFX에 보낸다. 볼륨과 음소거 설정은 이 버스에 연결한다.
- `assets/`에는 게임이 읽는 결과물, `artsource/`에는 모델·레시피·원화, `tools/`에는 빌드 도구를 둔다. [제작 파이프라인](../art/production-pipeline.md)에 공유 도구의 버전과 경로가 있다.
- 이후 저장은 영구 진행(이동 능력·지름길·발견)과 이번 런(시드·배치·강화)을 나눈다. 첫 저장 기능에서 버전을 기록하고 사망 직후와 게임을 다시 연 뒤의 결과를 각각 검사한다.

## Windows 빌드와 저장소

현재 작업 환경에는 표준판용 `4.7.2.stable` Windows 내보내기 템플릿이 설치되어 있다. 같은 버전의 템플릿을 사용해 다음 순서로 가져오기와 내보내기를 수행한다.

```powershell
$godotConsole = 'C:\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe'
& $godotConsole --headless --path . --import
& $godotConsole --headless --path . --quit-after 120
New-Item -ItemType Directory -Force build/windows | Out-Null
& $godotConsole --headless --path . --export-release 'Windows Desktop' 'build/windows/RequiemWaltz.exe'
```

생성된 `RequiemWaltz.exe`와 `RequiemWaltz.pck`를 같은 폴더에 둔다. 내보내기에는 게임 런타임 리소스가 들어간다. 프로젝트 원화·제작 스크립트·문서와 로컬 빌드는 엔진 스캔에서 제외한다.

로컬 Git 브랜치는 `main`이다. 코드·Godot 씬·원화·레시피·런타임 자산·임포트 설정과 스크립트 UID를 추적한다. 캐시·렌더 중간물·내보낸 실행 파일은 제외한다. GitHub 연결 및 Steam 테스트 단계는 [로드맵](../production/roadmap.md)에 있다.

## 첫 장면의 검증 결과

2026-11-18에 4.7.2 표준판으로 확인했다. 물리 키 입력으로 양쪽 벽까지 이동하고, 점프 후 재착지 신호와 먼지 생성·소멸, 소리 시작·종료가 각각 한 번 발생했다. 최초 배치 시 착지음은 0회였다. 가상 패드 입력으로 스틱 중앙 데드존과 십자키·점프 바인딩을 확인했다.

Windows x86_64 릴리스 EXE와 PCK를 같은 폴더에서 실행해 기본 장면이 정상 기동되는지 확인했다. [실제 Godot 화면](../art/first-causeway.png)은 640×360 게임 뷰포트에서 캡처했다. 저사양 기기 성능, 실물 패드 감각과 스피커 믹스는 첫 전투실 플레이테스트에서 확인한다.
