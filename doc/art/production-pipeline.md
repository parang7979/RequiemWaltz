# 도트 아트와 사운드 제작

첫 구역에서 확인할 장면은 달빛이 스치는 석조 회랑의 착지다. 멀리 구름이 흐르고 젖은 돌이 희미하게 빛나는 동안, 발이 닿는 순간 돌가루가 튀며 마른 충격음이 난다. 이 장면에서 정한 픽셀 크기, 재질과 타격의 명암 차이를 다음 방에서도 이어 간다.

제작 소스와 레시피는 `artsource/`, 게임에 쓰는 결과물은 `assets/`에 둔다. 편집한 원화, 사용한 팔레트, 소스의 출처와 이용 조건도 함께 기록한다. 도구 버전을 바꿀 때에는 같은 레시피로 한 장면을 다시 렌더해 색, 발 접지, 타이밍과 음량을 비교한다.

## 전투 캐릭터와 두 무기

1. 성인 여성 주인공의 옆모습 원화에서 무기를 쥔 손, 체중을 싣는 다리, 얼굴과 옷깃의 윤곽을 고른다. 원화와 대화 초상화에 공통으로 남길 특징을 YAML의 `brief`에 적는다. SpriteKiln에서는 이를 뼈대와 재질로 직접 모델링한다.
2. 프로젝트의 `artsource/spritekiln/spritekiln.toml`에 맞춰 좌우를 각각 렌더한다. 64픽셀 셀에서 대기 자세와 칼을 내뻗은 자세를 먼저 확인한다. 칼끝이 잘리면 셀 여백을 늘리고, 옆의 적과 발판은 같은 픽셀 밀도로 유지한다.
3. 첫 무기는 준비·타격·회수의 세 자세, 두 번째 무기는 두 실루엣 사이의 교체 자세부터 만든다. 지상과 공중에서 손목 소켓이 무기와 맞는지 확인한다. 히트박스와 취소 가능 시간은 GDScript 전투 데이터에서 관리하고, 칼끝의 궤적과 타격음은 그 타이밍에 맞춘다. 실제 명중 때만 피격 섬광과 충격음을 재생한다.
4. `validate`, 양쪽 `pose`, 클립별 `arcs`, 전체 `render` 순으로 검사한다. `export <spec> --engine godot --lit`로 내보낸 씬을 플레이어의 자식으로 배치한다. 재생성할 때 덮어쓰는 씬 밖에 충돌, 상태, 게임 로직을 둔다. 동일한 프레임 사각형과 발 피벗을 세 장의 아틀라스에 적용한다.

이 프로젝트에 생성한 첫 캐릭터의 입력 파일, 재생성 명령과 검사 결과는 [캐릭터 제작 기록](character-study.md)에서 확인한다.

## 광원과 발광

컬러·노멀에는 같은 프레임 배치, 크기, 등록점을 쓴다. `CanvasTexture`에 컬러와 노멀을 연결하고 `CanvasModulate`로 기본 밝기를 잡는다. 횃불이 인물의 좌우를 지나갈 때 광택이 광원 쪽으로 움직이는지 본다. 광원 높이와 세기는 석재·피부·비단 세 재질을 나란히 놓고 조정한다. 돌에 이미 그려진 강한 그림자가 광원과 충돌하면 평평한 채색본으로 다시 비교한다. [Godot 2D 조명과 그림자](https://docs.godotengine.org/en/stable/tutorials/2d/2d_lights_and_shadows.html)

SpriteKiln의 발광 아틀라스는 프레임을 동기화한 두 번째 스프라이트에 비조명 가산 합성으로 그린다. 주변 벽에 빛이 번져야 하는 횃불에만 작은 `PointLight2D`를 더한다. 칼날의 반짝임은 끝부분에 잠깐 남기고, 적이 공격을 예고하는 손과 착지 지점이 가장 긴 콤보 중에도 보이는지 살핀다. HUD는 별도 캔버스에서 아이콘과 숫자의 밝기를 유지한다.

## 타격과 착지의 시청각 동기화

발의 착지는 물리 프레임에서 공중→바닥으로 바뀌는 순간 한 번 발생시킨다. 바닥 재질과 접촉 좌표를 받아 석재에는 먼지와 짧은 마찰음, 물에는 물보라와 파문을 고른다. 타격은 휘두르는 소리·날의 궤적과 접촉 시의 소리·섬광을 분리한다. 헛친 동작과 맞힌 동작을 눈을 감고도 구분할 수 있는지 들어 본다.

석재 착지 샘플은 [먼지 레시피](../../artsource/pixelfx/landing_dust.mjs)와 [착지음 레시피](../../artsource/plinkfx/stone_land.json)로 재생성한다. 프로젝트 루트에서 Node 18 이상과 Python 3.10 이상으로 다음 명령을 실행한다.

```powershell
node artsource/render_landing.mjs
```

먼지는 발 피벗의 34×14픽셀 셀에 두 갈래로 퍼지고 마지막 프레임에서 사라진다. [생성한 씬](../../assets/vfx/landing_dust/landing_dust.tscn)의 `fx` 클립은 한 번 재생된다. 프로젝트용으로 직접 작성한 도형 레시피이며 PixelFX의 straight RGBA 출력을 그대로 사용한다. 공유 도구의 `LICENSE`와 `NOTICE.md`에 원저작자 표기가 있다.

[석재 착지음](../../assets/audio/stone_land.wav)은 PlinkFX의 CC0 `step-stone`을 바탕으로 돌 표면의 짧은 고역과 낮은 충격음을 조정한 0번 테이크다. 48 kHz에서 약 0.163초, 최대 순간 음량 −25.3 LUFS, 트루 피크 −1.51 dBTP로 측정했다. 네 테이크 모두 `check --cat footstep` 검사를 통과했다. 게임에서는 정규화를 끄고 적의 공격 예고음과 겹쳐 들으며 믹스를 결정한다.

## 대화 일러스트와 LiveIllustration

외부 R&D 위치는 `../LiveIllustration`이다. 로컬 README에서 Godot 4.7.2용 파츠 매니페스트와 광원 시험 씬을 확인했다. 현재 일반 임포터가 연결하는 텍스처는 알베도이고, 노멀·스페큘러·재질 마스크 연결은 실험 씬에서 별도 처리한다. 게임 도입 첫 단계는 원화 한 장을 한 인물의 대사 한 줄에 연결하는 것이다.

1. 같은 해상도의 컬러·정리한 노멀·스페큘러·재질 마스크를 준비한다. 눈과 옷깃의 특징이 전투 스프라이트와 일치하는지, 광원을 옮겼을 때 코와 입술의 명암이 뒤집히는지 확인한다.
2. 정지 초상화와 광원부터 연결한다. 다음 단계에서 숨결이나 눈 깜박임을 넣을 때 머리·눈꺼풀을 분리하고 움직여서 드러나는 밑그림을 보완한다. 파츠 내보내기, 재질 연결, 대사 재생은 각각 독립적으로 교체할 수 있게 둔다.
3. 세이브 플래그로 대화 표정과 광원을 재현하고 한글 줄바꿈, 즉시 표시, 입력 건너뛰기를 시험한다. 초상화는 대화 중 열리는 패널 안에서만 움직인다.

SpriteKiln의 자체 모델과 CC0 범위의 예제 부품을 쓸 수 있다. 공유 저장소의 Templar·Huntress 쇼케이스는 전시용이므로 게임의 의상·모델·팔레트는 프로젝트 원화에서 설계한다. PlinkFX의 도구 코드는 MIT, 카탈로그의 음원 정의와 그 렌더는 CC0다. 출시 후보를 묶을 때에는 프로젝트가 실제로 포함하는 애드온과 자산의 라이선스 원문을 동봉한다.
